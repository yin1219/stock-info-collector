# Windows manual acceptance register

本文件記錄 Windows 實機驗收，區分作者目視操作、維護者在隔離環境執行的自動測試與唯讀檢查。`Pending` 表示該項人工觀察尚未執行，`Partial` 不等於該項完整通過；只有具體證據支持的結果才可標為 `Accepted`。人工 `Pending` 不會推翻已由單元、整合、Playwright 或隔離 Windows 工作測試通過的 OpenSpec Scenario。紀錄只保留非敏感的日期、Windows build、應用版本、結果與證據；不得把自動測試說成作者目視驗收。

## 安全前提

- `WIN-GCAL-01`／`WIN-GCAL-PACKAGED-01` 是僅驗證登入的既有紀錄，當時沒有執行 Calendar 同步。作者其後明確同意另做一次 v2 正式主要 Calendar 的法說會同步驗收，可能新增尚未存在的未來活動；該次授權不包含執行 v1 或以正式 userData 跑標準測試。作者再後來要求 v2 安裝時接續 Windows 每日法說會工作；正式工作已受控建立並核對為唯一啟用的 19:00 工作。正式 19:00 自然觸發可繼續觀察，但每日觸發能力已由隔離近時每日工作與其他分層證據驗收。不要把 OAuth JSON、token、email、授權碼或敏感 log 放進驗收記錄。
- 登入啟動與 resume 測試優先使用隔離 Windows profile／VM；目前沒有此環境時保留待驗，不得拿正式 userData 或現有工作排程做破壞性測試。乾淨 profile 安裝不是本次驗收要求。
- 不執行 `node index.js`。作者沒有專用 Google 測試帳號；切換前的 v1/v2 同清單來源與正式 v2 Calendar 查重／補建證據見 `WIN-GCAL-LIVE-DEDUP-01`、`WIN-GCAL-RESTORE-01`。2026-10-22 作者要求在這些驗收後啟用唯一的 v2 每日排程，已保留 v1 為停用狀態；不得再啟用 v1 而不先停用並停止 v2，也不得複製 token。
- 保存非敏感證據，例如畫面截圖（遮蔽帳號）、安裝器版本、應用 log 的事件名稱及 SQLite 測試資料筆數。記錄中不得含憑證值。
