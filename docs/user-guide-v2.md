# 股市記者小幫手 v2 使用指南（開發驗收版）

> v2 已完成目前 Windows profile 的 per-user installer／捷徑／無 Node 啟動 smoke，以及以隔離測試資料進行的覆蓋升級／移除驗收；乾淨 profile 安裝不列為驗收要求。安裝版已驗證 Google OAuth 連線、正式 Calendar 查重及一筆刪除後的未來法說會補建。作者已確認登入啟動開／關及睡眠恢復；每日法說會 19:00 自然執行與其他 Windows 情境仍待驗收。v1 已停用且保留供回退，不可僅憑手動同步成功宣稱 v2 每日排程完成。

## 總覽與導覽

總覽顯示啟用中的關注公司、未讀重大訊息、當日違約揭露、未來 14 天法說會與資料來源健康摘要，並列出最新重大訊息、排程狀態及下一場法說會。桌面版使用左側導覽；窄視窗可按左上角按鈕開啟抽屜導覽；側欄及主內容各自捲動。

左側欄底部的「v2 · 版本 x.y.z」是目前實際執行的應用程式版號；覆蓋安裝後可先核對這一行，再測新版功能。

覆蓋安裝前應從舊版系統匣選「結束」；只關閉視窗仍會留在背景。若安裝後開啟捷徑卻仍顯示舊畫面，先檢查舊版是否仍在執行及捷徑目標，不要立刻重新執行 Google Calendar 同步。新版視窗須顯示預期的完整版本號，才開始驗收該版功能。

設定採「監控排程、通知、啟動與系統匣、資料管理」四分頁；登入啟動、測試通知及匯出各位於對應分頁。法說會舊版工作管理保留於監控排程的進階區。新增盤面紀錄及匯入格式說明見 [正式新版介面](reporter-ui-integration.md)。

## 建立或匯入關注公司

1. 在「關注公司」按「新增關注公司」，於對話框選擇上市或上櫃，輸入 4–6 位股票代號並選「新增公司」。新增時會查詢公司名錄確認市場與名稱；網路或名錄錯誤會顯示在畫面，不會建立不確定的公司資料。
2. 可搜尋名稱／代號，修改分類與備註，啟用、停用或移除關注公司。停用會保留在清單中供重新啟用；移除會從清單刪除關注關係，但公司資料及過往重大訊息、揭露紀錄仍保留。
3. 匯入舊清單時，先按「匯入舊版股票清單」，再從舊版 `config/default.json` 複製內容並貼到「舊版設定 JSON」。先按「預覽匯入」，檢視新增、略過、失敗數與逐筆原因；確認無誤後才按「確認並匯入」。這個流程讀取貼上的文字，不會修改舊設定檔。重複匯入會略過已存在公司。

若設定頁辨識出既有 v1 法說會每日工作，先用「核對舊版股號」比較 v1 現值與 v2 啟用清單，再按「確認套用到舊版工作」。即使 v2 已接管每日排程，只要 v1 工作仍可精確辨識、已停用並保留供回退，設定頁也會提供同樣的核對入口。確認後 v2 的新增、啟停、移除及匯入才會嘗試更新 v1 `StockNumbers`；其他 JSON 欄位保留，寫入前備份原檔。若檔案在核對後被外部修改或無法寫入，畫面會說明「v2 清單已更新，但 v1 未同步」，請重新核對；不要以為舊工作下一次會使用新股號。v2 清單完全沒有啟用公司時，不會把空字串寫進 v1 設定。隔離預覽不會讀寫真正的 v1 設定或 Windows 工作。

## 重大訊息與來源狀態

- 目前即時來源改用 MOPS 官方「公告快易查」依日期查詢上市／上櫃重大訊息及官方明細；它能提供真實公告，但完整性尚未證實，畫面固定標示「部分降級」與可能漏筆警示，不能視為完整每小時同步。官方明確回覆「查無公告資料」時會另行顯示，不會與 RSS 的 HTTP 404 混成同一錯誤；這仍不能證明當日真的零筆。只有查詢失敗時才嘗試 Big5 RSS 備援；備援成功也只算降級。每日 TWSE／TPEX 對帳可補回官網當次未列的紀錄，但需以單筆發言日核對是否為同日公告，並查看來源狀態判斷資料時效。
- 重大訊息頁會列出最近一次 job 狀態與各來源結果；TWSE／TPEX 每日對帳顯示的是「出表日期」，不等於每筆公告的「發言日期」，對帳筆數也不等於當日新公告筆數。空清單只代表目前查詢條件沒有已保存事件；若來源失敗／降級，狀態區會另行說明，不能據此推論「官方沒有公告」。
- 列表預設只顯示目前啟用的關注公司公告，頁尾顯示目前篩選後的公告筆數；若要查已保存的其他公司公告，勾選「顯示全部公告」，頁尾筆數也隨篩選更新。點選任一摘要會在該列下方展開完整內容，再點同列或點「關閉」可收合；點另一列時前一列自動收合。移除關注公司只會改變預設列表範圍，不刪除過去保存的公告。
- 在單筆公告詳情按「刪除此筆本機公告」後，程式會再次要求確認。確認後該筆從本機清單隱藏，舊通知、公告內容與刪除稽核紀錄仍保留；官方來源再次抓到相同公告時會恢復顯示，若仍關注該公司，可能再收到一次通知。這可用於重測通知，但不代表官方發布一筆新的公告，也不會刪除官方資料。作者已回報新安裝版軟刪後手動重查再次收到通知；若來源失敗或日期過期，仍不能把該次檢查視為完整成功。
- TWSE 與 TPEX 每日對帳會在每日違約交割工作時一併執行，補回啟用關注公司當日漏接的重大訊息。新補回事件會標成「上市／上櫃結構化每日對帳」，並納入新事件通知；對帳來源的失敗狀態也會出現在重大訊息來源狀態區。
- 更正／補充公告會以獨立版本保存，詳情可查看原公告與後續版本。來源網址供人工核對官方公告。

## 全市場違約交割

頁面可依日期與上市／上櫃篩選，未關注公司也會保留在全市場結果中，關注公司以標記強調。列表上方的來源狀態會分市場顯示繁中結果；只有所選市場均取得符合查詢日期的官方明確零筆回應，空列表才顯示「當日無個股達違約資訊揭露標準」。狀態區若顯示「官方尚未更新」或「來源失敗」，空列表與頂端筆數會分別明示「不能判定為零筆」與「未確認」，不能把空清單讀成零筆；可查看資料日期、錯誤與預計重試時間。TWSE 以儀表板 BFIGTU 日期範圍回應的最近申報日為準；非交易日可能晚於所選日期：

| 狀態 | 意義 |
| --- | --- |
| 「資料完整」 | 來源資料日期符合查詢日期且取得完整回應；資料列為零時才可表示當日無揭露 |
| 「本日無揭露」 | 官方日期正確且明確回傳零筆（內部市場狀態 `empty_success`） |
| 「官方尚未更新」 | 官方回應仍是較舊日期；預設 19:00 再查一次，不視為零筆 |
| 「來源失敗」 | 網路、格式或來源回應失敗；不能解讀為無揭露 |
| 「資料來源部分降級」 | 只有部分市場成功；請查看各市場狀態 |

預設違約交割工作時間為 Asia/Taipei 每日 18:30；若官方資料尚未更新，排程器只安排一次 19:00 重試。重大訊息監控預設全天、每 60 分鐘一次，也支援 15／30／60／120 分鐘間隔與跨午夜時段。「開始／結束時間」界定允許檢查的時段；間隔從上次檢查時間計算，15 分鐘不保證落在整點、15、30、45 分。到「設定」頁可啟停兩種工作、設定監控時段與頻率、每日違約交割時間、是否接收「本日無違約揭露」通知（預設啟用），查看上次成功／結果／錯誤／預計下次執行時間，或立即檢查。沒有新公告時不會發重大訊息通知。工作已在執行時不會重複建立，畫面會說明仍在執行；完成後同一分鐘內再按會重新檢查來源，違約交割帶動的重大訊息對帳也會重新執行。手動檢查失敗會顯示來源錯誤，不會當成空結果。

隔離開發／自動化測試模式預設不連 live 官方網站，「立即檢查」會停用並顯示原因。若維護者要人工檢查真實來源，可在另一個暫存 userData 以 `REPORTER_TEST_LIVE_SOURCES=1` 明確啟動；此模式只在按下按鈕時抓取，沒有自動排程或 Windows 通知，且結果只寫入該暫存 SQLite。這不是標準測試，也不會觸發 Google Calendar 同步；請勿在此模式按 Calendar 同步。

## 測試 Windows 通知

在正式安裝版的「設定」頁按「發送測試通知」。通知標題與內容都會表明這只是本機測試，不是真實重大訊息；點擊通知會返回設定頁。按鈕顯示「Windows 已接受測試通知顯示要求」僅代表原生通知元件回報顯示事件，若眼前沒看到 Toast，請檢查 Windows 通知設定並記下時間查看 `userData/logs/application.log` 的 `test-notification-failed`（若有）。此操作不抓官方資料、不觸碰 Google Calendar、不刪除或重設已保存公告，也不建立通知 outbox 紀錄。隔離測試模式不發 Windows Toast，按鈕會明示「隔離測試模式不顯示 Windows 通知」。作者已回報實際安裝版的即時測試 Toast 可見並可點擊返回，記於 `WIN-TEST-TOAST-01`；一分鐘後測試仍待驗。

若要連同背景運作一起測，可按「一分鐘後發送測試通知」再關閉主視窗，但不要從系統匣選「結束」；程式留在系統匣時，約一分鐘後應顯示測試 Toast，點擊後回到設定頁。明確結束會取消這次測試排程。這不是重大訊息排程，不抓官方資料、不修改公告或通知去重，也不寫 Calendar；作者已在安裝版看到關窗留在系統匣後的通知，點擊返回及明確結束取消仍待 `WIN-TRAY-DELAYED-TOAST-01` 驗收。

## 本機資料、log 與備份復原

- 在「設定」→「本機資料備份」選擇「匯出資料」，用系統另存對話框選擇 JSON 檔位置；取消不會建立檔案。成功會顯示完整目的位置，寫入失敗會顯示錯誤。匯出為版本化格式，包含業務資料與非敏感設定，不含可重用 OAuth 憑證／token，也不會覆寫同名檔案。
- 資料庫、log 與加密 token 位於 Electron `app.getPath('userData')`，不是安裝目錄；診斷檔在其 `logs/application.log`。Windows 實際資料夾名稱由 Electron app identity 決定。此版使用檔案診斷紀錄，不寫入 Windows Event Log；事件檢視器沒有小幫手事件時，請改查該檔。Google 連線或同步失敗會留下 `google-calendar-action-failed` 與操作名稱。發生錯誤時先記錄時間、畫面操作與 log 中對應事件；分享 log 前先檢查是否含個資。
- 關閉應用程式後，備份整個 userData 目錄；不要只複製 SQLite 主檔而漏掉 WAL/SHM 檔。舊版 `token.json`、`token_bak.json`、`credentials.json` 是敏感檔，不要放進 issue、fixture 或匯出檔。
- 復原時先結束程式，把現有 userData 目錄改名保留，再把完整備份目錄放回原位置。若 migration 啟動失敗，保留 log 與資料庫旁的 `.pre-v<版本>.backup`，先不要刪除資料。
- v2 Google OAuth desktop flow、法說會列表、Calendar 同步 UI 與使用者確認的一次性舊 token 遷移已接入；一般測試只使用 fake OAuth/Calendar。使用者本人已在安裝版驗證連線、中斷及重新連線。正式 Calendar 已驗證既有活動查重，以及 1.0.13 對一筆已刪除未來活動的補建且無重複；v1 成功自然週期及 v2 每日工作切換仍未驗收。不要手動複製 v1 token 至 v2；若要遷移，請使用「法說會」頁的遷移按鈕與確認流程。

## 法說會與 Google Calendar

1. 開啟「法說會」頁並選擇「連線 Google Calendar」。OAuth client 由應用程式提供，一般使用者不需建立、下載或匯入 JSON。
2. 畫面會提示等待系統瀏覽器授權；請在 Google 登入並同意 Calendar 存取。授權回到本機 loopback callback，成功換取 token 後瀏覽器才會顯示授權完成；使用者 token 由 Windows `safeStorage` 加密後存入 userData，應用程式提供的 client 設定並非使用者 token。畫面只顯示狀態，不會讀取或顯示 token。若沒有看見瀏覽器，請查看 `logs/application.log` 是否有 `google-oauth-browser-launch-requested`、`google-oauth-browser-used-system-fallback` 或 `google-oauth-browser-open-failed`；開啟請求被接受不等於瀏覽器已顯示在前景。
3. 登入／連線本身不會擷取或寫入。只有確認 v1 與 v2 每日工作都不存在、且 v2 已有啟用的關注公司與有效 Google 授權時，v2 才嘗試建立 Windows 每日 19:00 的無視窗法說會工作；到「設定」→「法說會每日工作」確認是否就緒。若看到已停用且停止的 v1 工作，代表目前沒有啟用中的法說會排程；正式來源、去重與 Calendar 寫入驗收通過後，按「切換為 v2 每日排程」並再次確認，才會建立 v2 工作。已停用的 v1 工作會保留供回退；v1 重新啟用、仍在執行、工作查詢失敗或 Google／關注清單未就緒時不切換。建立後仍須查看首次執行結果，不能只因工作存在就認定每日同步成功。手動同步可能新增主要 Calendar 活動；v1 仍啟用、正在執行或工作狀態未知時仍會拒絕。

從舊版 v2 升級時，若既有每日 17:45 工作與停用的 v1 工作都能精確辨識，新版會先把原工作 XML 備份到 v2 userData 的 windows-task-backups，再將同一工作改為 19:00。若名稱、擁有者、動作或唯一寫入者無法確認，會顯示未就緒，不會修改其他工作；可在設定頁重試並核對下次執行時間。

若 v2 每日工作之後持續失敗，先在 Windows「工作排程器」停用 `StockReporterAssistant-ConferenceDaily` 並確認它已停止；檢查保留的 v1 執行檔、`config/default.json` 股號與原授權仍可用後，才由使用者決定是否重新啟用 `stock-info-collector-daily-work`。不可同時啟用兩個每日工作，也不要直接刪 v2 工作或複製 token。回退前可先由設定頁查看 Windows 結果碼，並查 `userData/logs/application.log` 的 `conference-scheduled-finished`／`conference-scheduled-failed` 事件；結果碼 0 只代表工作啟動成功，仍須核對 v2 的工作紀錄是否為 `complete`。
4. 項目狀態「待同步、已存在、已同步、同步失敗」分別表示待處理、查重找到既有事件、成功寫入或單筆失敗；新擷取的項目可選「開啟法說會來源」查看 MOPS 官方頁。Google 憑證遭拒時停止後續 Calendar 請求、保留待同步項目並提示重新授權。選「中斷 Google Calendar」會嘗試向 Google 撤銷授權，並清除 v2 userData 內加密保存的使用者 token；即使 Google 回覆該 token 已失效，本機仍應顯示「尚未連線」。若其他錯誤使 Google 端撤銷無法確認，畫面會警示本機已中斷但遠端狀態未確認。此操作不刪 v1 的 `token.json`、OAuth client 設定、法說會紀錄或既有 Google Calendar 活動；作者已在 1.0.7 驗證中斷與重新連線。

已保存為「已存在／已同步」只代表上次的結果，不能保證 Google 上現在仍有該筆。新版每次同步都會重新查詢仍在未來的啟用公司場次；若你在 Google 手動刪除事件，下次查詢確定缺少時會補建，即使 MOPS 目前頁面已不再列出該場次。過期或停用公司的場次不會補建；Google 查詢失敗時也不會猜測為不存在。此補建行為已通過離線模擬測試；作者也確認 1.0.13 正式帳號刪除後補建，且同時段同名稱只有一筆。

使用者本人已在隔離開發版與本機安裝版完成 Google OAuth 連線；正式 Calendar 查重與一筆未來活動補建已通過。舊 token 真實資料遷移、v1/v2 完整週期比較與每日工作切換尚未完成驗收，因此不應直接依賴 v2 取代既有正式採訪行事曆排程。

## 背景執行與系統匣

正式模式中，關閉主視窗只會隱藏視窗，排程留在背景執行。按系統匣圖示可重新顯示視窗；匣選單「結束」會停止 scheduler 並結束應用程式。一般隔離測試模式不建立系統匣；只有 Electron tray E2E 同時設 `REPORTER_USER_DATA_DIR` 與 `REPORTER_TEST_TRAY=1` 時才顯示測試視窗及建立暫時圖示，而且 scheduler 仍停用。Windows tray 圖示／選單完整人工驗收尚待完成。全新正式使用者資料預設啟用「登入 Windows 時啟動」及「啟動後縮到系統匣」；覆蓋升級保留原有設定，隔離預覽不操作 Windows 啟動項。切換後會立即儲存並讀回作業系統狀態；若 Windows 停用了登入啟動項，畫面會提示。作者已回報實際登出／登入驗證啟用與停用兩種狀態，紀錄見 `docs/windows-manual-acceptance.md`。

## 安裝與驗收狀態

Windows Squirrel 每使用者安裝包（含應用與 setup 圖示）可由 `npm run make` 產生：
