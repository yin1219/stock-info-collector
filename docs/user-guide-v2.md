# 股市記者小幫手 v2 使用指南（開發驗收版）

> v2 已完成目前 Windows profile 的先前 per-user installer／捷徑／無 Node 啟動 smoke，以及以隔離測試資料進行的覆蓋升級／移除驗收；乾淨 profile 安裝不列為驗收要求。使用者已在隔離開發版與先前 1.0.0 安裝版完成 Google OAuth 連線；新產出的 1.0.1 installer 已內建應用程式 client 並通過隔離 packaged smoke，但尚未安裝驗收，登入啟動等驗收也仍待完成。請勿用 v2 取代目前可用的 v1 行事曆流程；本指南不代表所有正式環境情境已驗收。

## 總覽與導覽

總覽顯示啟用中的關注公司、未讀重大訊息、當日違約揭露、未來 14 天法說會與資料來源健康摘要，並列出最新重大訊息、排程狀態及下一場法說會。桌面版使用左側導覽；窄視窗會改為可橫向捲動的導覽列。

## 建立或匯入關注公司

1. 在「關注公司」選擇上市或上櫃，輸入 4–6 位股票代號並選「新增公司」。新增時會查詢公司名錄確認市場與名稱；網路或名錄錯誤會顯示在畫面，不會建立不確定的公司資料。
2. 可搜尋名稱／代號，修改分類與備註，啟用、停用或移除關注公司。停用會保留在清單中供重新啟用；移除會從清單刪除關注關係，但公司資料及過往重大訊息、揭露紀錄仍保留。
3. 匯入舊清單時，從舊版 `config/default.json` 複製內容並貼到「設定 JSON」。先按「預覽匯入」，檢視新增、略過、失敗數與逐筆原因；確認無誤後才按「確認並匯入」。這個流程讀取貼上的文字，不會修改舊設定檔。重複匯入會略過已存在公司。

## 重大訊息與來源狀態

- 目前即時來源改用 MOPS 官方「公告快易查」依日期查詢上市／上櫃重大訊息及官方明細；它能提供真實公告，但已觀察到漏筆，畫面固定標示「部分降級」與原因，不能視為完整每小時同步。來源查詢失敗時仍會嘗試 Big5 RSS 備援；備援成功也只算降級。每日 TWSE／TPEX 對帳可補回遺漏，但資料時效仍需查看來源狀態。
- 重大訊息頁會列出最近一次 job 狀態、各來源結果與資料日期。空清單只代表目前查詢條件沒有已保存事件；若來源失敗／降級，狀態區會另行說明，不能據此推論「官方沒有公告」。
- 列表預設只顯示目前啟用的關注公司公告，筆數標為「關注」；若要查已保存的其他公司公告，勾選「顯示全部公告」，筆數會標為「全部」。點選任一摘要會在該列下方展開完整內容，再點同列或點「關閉」可收合；點另一列時前一列自動收合。移除關注公司只會改變預設列表範圍，不刪除過去保存的公告。
- TWSE 與 TPEX 每日對帳會在每日違約交割工作時一併執行，補回啟用關注公司當日漏接的重大訊息。新補回事件會標成「上市／上櫃結構化每日對帳」，並納入新事件通知；對帳來源的失敗狀態也會出現在重大訊息來源狀態區。
- 更正／補充公告會以獨立版本保存，詳情可查看原公告與後續版本。來源網址供人工核對官方公告。

## 全市場違約交割

頁面可依日期與上市／上櫃篩選，未關注公司也會保留在全市場結果中，關注公司以標記強調。列表上方的來源狀態會分市場顯示繁中結果；只有所選市場均取得符合查詢日期的官方明確零筆回應，空列表才顯示「當日無個股達違約資訊揭露標準」。狀態區若顯示「官方尚未更新」或「來源失敗」，空列表與頂端筆數會分別明示「不能判定為零筆」與「未確認」，不能把空清單讀成零筆；可查看資料日期、錯誤與預計重試時間。TWSE 以儀表板 BFIGTU 日期範圍回應的最近申報日為準；非交易日可能晚於所選日期：

| 狀態 | 意義 |
| --- | --- |
| 「資料完整」 | 來源資料日期符合查詢日期且取得完整回應；資料列為零時才可表示當日無揭露 |
| 「本日無揭露」 | 官方日期正確且明確回傳零筆（內部市場狀態 `empty_success`） |
| 「官方尚未更新」 | 官方回應仍是較舊日期；預設 19:00 再查一次，不視為零筆 |
| 「來源失敗」 | 網路、格式或來源回應失敗；不能解讀為無揭露 |
| 「資料來源部分降級」 | 只有部分市場成功；請查看各市場狀態 |

預設違約交割工作時間為 Asia/Taipei 每日 18:30；若官方資料尚未更新，排程器只安排一次 19:00 重試。重大訊息監控預設全天、每 60 分鐘一次，也支援 15／30／60／120 分鐘間隔與跨午夜時段。到「設定」頁可啟停兩種工作、設定監控時段與頻率、每日違約交割時間、是否接收「本日無違約揭露」通知（預設啟用），查看上次成功／結果／錯誤／預計下次執行時間，或立即檢查。工作已在執行時不會重複建立，畫面會說明仍在執行；完成後同一分鐘內再按會重新檢查來源，違約交割帶動的重大訊息對帳也會重新執行。手動檢查失敗會顯示來源錯誤，不會當成空結果。

隔離開發／自動化測試模式預設不連 live 官方網站，「立即檢查」會停用並顯示原因。若維護者要人工檢查真實來源，可在另一個暫存 userData 以 `REPORTER_TEST_LIVE_SOURCES=1` 明確啟動；此模式只在按下按鈕時抓取，沒有自動排程或 Windows 通知，且結果只寫入該暫存 SQLite。這不是標準測試，也不會觸發 Google Calendar 同步；請勿在此模式按 Calendar 同步。

## 本機資料、log 與備份復原

- 在「設定」→「本機資料備份」選擇「匯出資料」，用系統另存對話框選擇 JSON 檔位置；取消不會建立檔案。成功會顯示完整目的位置，寫入失敗會顯示錯誤。匯出為版本化格式，包含業務資料與非敏感設定，不含可重用 OAuth 憑證／token，也不會覆寫同名檔案。
- 資料庫、log 與加密 token 位於 Electron `app.getPath('userData')`，不是安裝目錄；診斷檔在其 `logs/application.log`。Windows 實際資料夾名稱由 Electron app identity 決定。此版使用檔案診斷紀錄，不寫入 Windows Event Log；事件檢視器沒有小幫手事件時，請改查該檔。Google 連線或同步失敗會留下 `google-calendar-action-failed` 與操作名稱。發生錯誤時先記錄時間、畫面操作與 log 中對應事件；分享 log 前先檢查是否含個資。
- 關閉應用程式後，備份整個 userData 目錄；不要只複製 SQLite 主檔而漏掉 WAL/SHM 檔。舊版 `token.json`、`token_bak.json`、`credentials.json` 是敏感檔，不要放進 issue、fixture 或匯出檔。
- 復原時先結束程式，把現有 userData 目錄改名保留，再把完整備份目錄放回原位置。若 migration 啟動失敗，保留 log 與資料庫旁的 `.pre-v<版本>.backup`，先不要刪除資料。
- v2 Google OAuth desktop flow、法說會列表、Calendar 同步 UI 與使用者確認的一次性舊 token 遷移已接入；一般測試只使用 fake OAuth/Calendar。使用者本人已在隔離開發版與本機安裝版完成連線驗收，均未按同步；Calendar 寫入仍未驗收。不要手動複製 v1 token 至 v2；若要遷移，請使用「法說會」頁的遷移按鈕與確認流程。

## 法說會與 Google Calendar

1. 開啟「法說會」頁並選擇「連線 Google Calendar」。OAuth client 由應用程式提供，一般使用者不需建立、下載或匯入 JSON。
2. 畫面會提示等待系統瀏覽器授權；請在 Google 登入並同意 Calendar 存取。授權回到本機 loopback callback，成功換取 token 後瀏覽器才會顯示授權完成；使用者 token 由 Windows `safeStorage` 加密後存入 userData，應用程式提供的 client 設定並非使用者 token。畫面只顯示狀態，不會讀取或顯示 token。若沒有看見瀏覽器，請查看 `logs/application.log` 是否有 `google-oauth-browser-launch-requested`、`google-oauth-browser-used-system-fallback` 或 `google-oauth-browser-open-failed`；開啟請求被接受不等於瀏覽器已顯示在前景。
3. 只有按「立即擷取並同步法說會」才會查詢啟用中的關注公司、讀取 MOPS 法說會頁並將不存在的未來場次寫入主要 Google Calendar。登入／連線本身不會執行同步或寫入。
4. 項目狀態「待同步、已存在、已同步、同步失敗」分別表示待處理、查重找到既有事件、成功寫入或單筆失敗；新擷取的項目可選「開啟法說會來源」查看 MOPS 官方頁。Google 憑證遭拒時停止後續 Calendar 請求、保留待同步項目並提示重新授權；選「中斷 Google Calendar」可撤銷並清除已保存的授權 token。

使用者本人已在隔離開發版與本機安裝版完成 Google OAuth 連線（均未執行 Calendar 同步寫入）；MOPS 真實來源、Calendar 寫入與舊 token 真實資料遷移尚未完成驗收。在完成這些流程前，不應依賴 v2 自動化正式採訪行事曆。

## 背景執行與系統匣

正式模式中，關閉主視窗只會隱藏視窗，排程留在背景執行。按系統匣圖示可重新顯示視窗；匣選單「結束」會停止 scheduler 並結束應用程式。一般隔離測試模式不建立系統匣；只有 Electron tray E2E 同時設 `REPORTER_USER_DATA_DIR` 與 `REPORTER_TEST_TRAY=1` 時才顯示測試視窗及建立暫時圖示，而且 scheduler 仍停用。Windows tray 圖示／選單人工驗收尚待完成。「登入 Windows 時啟動」及「啟動後縮到系統匣」設定已提供，但啟用後須重新登入才能驗證；目前尚無該項人工驗收紀錄。其餘真人驗收步驟與待填紀錄欄位見 `docs/windows-manual-acceptance.md`。

## 安裝與驗收狀態

Windows Squirrel 每使用者安裝包（含應用與 setup 圖示）可由 `npm run make` 產生：

`artifacts/forge-out/make/squirrel.windows/x64/StockReporterAssistantSetup.exe`

install/update 事件會建立桌面與開始功能表捷徑，uninstall 會移除程式版本檔與捷徑，並保留和安裝目錄分離的 userData。若解除安裝前仍需歷史紀錄，先備份 userData；若確認不再需要，解除安裝後再自行刪除該資料夾。packaged EXE smoke、目前 profile 安裝與捷徑、無 Node／管理員權限啟動、1.0.1→1.0.2 覆蓋升級保留測試 SQLite 標記，以及移除後保留 userData 的驗收均記錄於 `docs/windows-install-acceptance.md`。這次使用隔離測試資料目錄，未讀取或修改既有正式 userData；正式 Google Calendar 同步與寫入仍未驗收，完成前仍以 v1 執行日常法說會行事曆流程。
