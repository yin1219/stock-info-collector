# Design

## Context
既有 Electron/React/SQLite 應用已有可信 IPC 與背景生命週期。原始 CMoney XLSX 是本機資料，不得打包。

## Goals / Non-Goals
以全量日資料重算 2020 年以來排名。首版只做盤後確認；不付資料費、不爬新聞全文、不改 Windows Calendar 工作。

## Decisions
- 日資料使用來源、日期、分類為鍵，保留匯入修訂稽核；金額使用整數元，指數使用百分之一點。
- 外資分類使用至少三個重疊日期的CMoney與TWSE原始組成核對，容許每日期一萬元的匯出精度差。必須可唯一辨識含或不含外資自營商才啟用銜接；任一修訂衝突會撤回核對結果。原始列不改寫，排名時才轉換口徑。
- 連續期間以已知交易日曆核對，至少二日，零、反向、缺資料中斷。同額同名次；每段只計一次，仍持續的段落可排名。
- 指數以同來源日高低減前一交易日收盤。當日只有官方日資料可確認，CMoney 當日列待確認。
- TWSE OpenAPI 更新指數及交易日曆。FinMind 必須通過 live 數值及免費使用範圍核對才可啟用；本次未知視為未通過，明確使用手動 CSV fallback。
- 15:30 後每個交易日提醒一次；啟動/resume 補查，隔離 userData 不自動連來源。每日期/指標通知有持久去重鍵，同日修訂不再次通知。
- 新聞證據是具來源的主張，記錄發稿時間、事件日期、口徑、數字及當時名次；與日資料重算結果並列。近24個月搜尋加上前三名歷史期間延伸，無報導不等於資料錯。

## Risks / Trade-offs
來源延遲 → 顯示待確認，不冒充零筆。分類不一致 → 拒絕混接並提供原因。新聞約數或修訂 → 保留差異，不覆寫日資料。

## Migration Plan
新增 migration 並沿用升級前備份。新增頁面與窄 IPC，不動正式 userData 做測試。

## 每日指數與歷史補匯
官方最新月份使用日期鍵合併至SQLite，保留其他月份與CMoney補匯。官方同日列優先，已知缺少前一交易日收盤時暫不計算漲跌點。狀態顯示官方資料日、當次程序的最近檢查時間及由保存日期交叉核對的缺日。畫面可見時每分鐘讀取SQLite，focus時刷新，以請求序號阻止舊背景快照覆蓋手動更新。隔離與無視窗Calendar入口共用同一自動更新旗標。
