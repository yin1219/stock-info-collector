# Spec Delta

## Purpose

定義本機資料、設定、執行歷程與敏感憑證的持久化及可攜性，讓使用者可追溯監控結果並能安全備份或移轉。

## ADDED Requirements

### Requirement: 結構化資料持久保存在本機
系統 SHALL 使用本機交易式資料庫保存關注清單、重大訊息、違約揭露、法說會、工作執行與通知紀錄。

#### Scenario: 應用程式非正常結束後重啟
- **WHEN** 已提交的資料在應用程式重新啟動後被查詢
- **THEN** 系統仍能讀取該資料且不因中斷產生半套更新

### Requirement: 使用者可備份與匯出資料
系統 SHALL 提供使用者觸發的備份或匯出功能，產出可辨識版本且不包含可直接使用之敏感憑證的檔案。

#### Scenario: 匯出使用者資料
- **WHEN** 使用者選擇匯出並指定可寫入位置
- **THEN** 系統建立含設定與業務紀錄的匯出檔，並明確回報成功位置或失敗原因

### Requirement: 敏感憑證受到作業系統保護
系統 MUST 將 OAuth token 等敏感資料存放於應用程式使用者資料區，並使用目前 Windows 使用者範圍的作業系統保護能力加密。

#### Scenario: 檢視一般設定或匯出檔
- **WHEN** 使用者開啟應用程式設定檔、資料庫匯出或一般診斷紀錄
- **THEN** 內容不得包含可直接重用的明文 refresh token 或 access token

### Requirement: 資料庫遷移具備版本與回復策略
系統 MUST 記錄資料結構版本，並在升級前建立可回復點；遷移失敗時不得以部分更新的資料庫繼續執行監控。

#### Scenario: 結構遷移失敗
- **WHEN** 新版啟動時無法完整套用資料庫遷移
- **THEN** 系統停止背景工作、保留遷移前資料並顯示可採取的復原資訊
