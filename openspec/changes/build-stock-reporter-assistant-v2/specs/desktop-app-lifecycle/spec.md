# Spec Delta

## Purpose

定義 Windows 桌面應用在前景、背景、登入啟動與睡眠喚醒時的可觀察行為，確保監控服務不因關閉主視窗或短暫休眠而意外中斷。

## ADDED Requirements

### Requirement: 應用程式可在系統匣持續執行
系統 SHALL 在使用者關閉主視窗時隱藏視窗並繼續於系統匣執行，除非使用者明確選擇結束應用程式。

#### Scenario: 關閉主視窗
- **WHEN** 使用者按下主視窗關閉按鈕
- **THEN** 系統隱藏主視窗、保留排程與監控，並在系統匣提供重新開啟與結束選項

#### Scenario: 從系統匣結束
- **WHEN** 使用者在系統匣選單選擇結束
- **THEN** 系統停止排程、完成資料寫入並結束處理程序

### Requirement: 應用程式維持單一執行個體
系統 MUST 防止同一 Windows 使用者同時啟動多個應用程式執行個體。

#### Scenario: 重複啟動
- **WHEN** 應用程式已在背景執行且使用者再次開啟捷徑
- **THEN** 系統顯示既有主視窗且不建立第二組排程

### Requirement: 畫面顯示目前執行版本
系統 SHALL 在主畫面持續顯示目前執行中的應用程式完整版本號，讓使用者辨識已安裝版本，不得把 Electron runtime 版本誤認為產品版本。

#### Scenario: 開啟已安裝版本
- **WHEN** 使用者開啟 v2 主視窗
- **THEN** 側邊資訊顯示目前應用程式的主版、次版及修補版號，且資料來自執行中的應用程式

### Requirement: 登入啟動可由使用者控制
系統 SHALL 提供設定讓使用者啟用或停用 Windows 登入後自動啟動，並顯示目前生效狀態。全新正式使用者資料預設啟用登入啟動及啟動後縮到系統匣；覆蓋升級 SHALL 保留既有使用者的登入啟動選擇。

#### Scenario: 全新正式資料預設背景登入啟動
- **WHEN** 安裝版首次建立使用者資料且 Windows 尚無此應用的登入啟動設定
- **THEN** 系統預設啟用登入 Windows 時啟動與啟動後縮到系統匣，畫面顯示實際生效狀態；隔離預覽與既有使用者設定不得被覆寫

#### Scenario: 啟用登入啟動
- **WHEN** 使用者啟用設定並重新登入 Windows
- **THEN** 應用程式在背景啟動且監控排程開始運作

#### Scenario: 切換登入啟動設定
- **WHEN** 使用者在設定頁切換登入啟動或啟動後縮到系統匣
- **THEN** 系統立即嘗試持久化並顯示實際生效或失敗狀態，不得只呈現尚未儲存的勾選值

### Requirement: 喚醒後檢查遺漏工作
系統 SHALL 在電腦自睡眠喚醒或應用程式重新啟動時，判斷是否有需要補查的監控工作。

#### Scenario: 睡眠跨過預定檢查時間
- **WHEN** 裝置喚醒且某項工作的最後成功時間早於其補查門檻
- **THEN** 系統安排一次補查且不重複建立同一工作

### Requirement: 開發預覽可由使用者在互動桌面操作
系統 SHALL 提供不安裝新版 installer 的開發預覽啟動入口，以獨立暫存 `userData` 開啟可見視窗，標明隔離預覽且不啟用正式排程；不得把工具程序已建立視窗或 Playwright 找到視窗當成使用者親眼可見的證據。

#### Scenario: 使用者從檔案總管啟動隔離預覽
- **WHEN** 使用者從自己的互動桌面啟動開發預覽入口
- **THEN** 畫面顯示可辨識的隔離預覽標題，可操作 v2 頁面，不讀寫安裝版 `userData`，也不需重新安裝應用程式
