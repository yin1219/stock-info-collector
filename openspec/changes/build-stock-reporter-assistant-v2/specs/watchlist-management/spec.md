# Spec Delta

## Purpose

定義記者可以透過圖形介面維護上市櫃關注公司，並將既有設定安全匯入，以供重大訊息、違約揭露及畫面標示共同使用。

## ADDED Requirements

### Requirement: 使用者可管理關注公司
系統 SHALL 允許使用者新增、編輯、啟用、停用與移除關注公司，並保存股票代號、公司名稱、市場及選填備註或分類。

#### Scenario: 新增有效公司
- **WHEN** 使用者輸入可辨識的上市或上櫃股票代號並儲存
- **THEN** 系統保存該公司並立即將其套用至後續監控

#### Scenario: 輸入無效代號
- **WHEN** 使用者輸入無法由目前公司名錄辨識的股票代號
- **THEN** 系統拒絕儲存並顯示可理解的驗證訊息

### Requirement: 停用不刪除歷史
系統 MUST 在停用或移除關注公司後保留已收集的歷史訊息與工作紀錄。

#### Scenario: 停用公司
- **WHEN** 使用者停用某關注公司
- **THEN** 系統停止以該公司作為重大訊息篩選條件，但歷史資料仍可查閱

### Requirement: 可匯入既有股票清單
系統 SHALL 在首次設定時支援從既有 `config/default.json` 匯入股票代號，並避免重複建立相同市場與代號的公司。

#### Scenario: 匯入含重複代號的設定
- **WHEN** 使用者選擇匯入且清單包含已存在的公司
- **THEN** 系統只新增缺少的公司並回報新增、略過與失敗數量

### Requirement: 共存期間管理 v1 法說會股號設定
系統 SHALL 在辨識並經使用者確認既有 v1 工作與其設定檔後，讓 v2 啟用的關注股號套用到該工作使用的 `config/default.json` 的 `StockNumbers`。v2 已成為唯一啟用的每日工作而 v1 停用保留供回退時，仍 SHALL 提供相同的核對與套用入口。寫入 MUST 只變更此欄位、保留其他 JSON 欄位，先建立可復原備份並以原子替換防止部分寫入；不得未經核對就覆蓋原有 v1 股號。

#### Scenario: 關注清單變更套用舊工作
- **WHEN** 使用者完成舊清單匯入／核對後，在 v2 新增、停用或移除關注公司
- **THEN** v1 設定的 `StockNumbers` 與 v2 啟用股號一致，畫面回報實際套用結果，舊工作下次執行會使用該清單

#### Scenario: 舊設定被外部修改或無法寫入
- **WHEN** v1 設定檔在核對後被外部修改、無法讀取或無法安全寫入
- **THEN** 系統保留原檔與既有工作，不回報同步成功，並告知新關注公司尚未套用法說會排程及可採取的復原步驟

#### Scenario: 共存時移除最後一間啟用公司
- **WHEN** v1 每日工作仍受管，而 v2 關注清單沒有任何啟用公司
- **THEN** 系統 SHALL 不把空字串寫入 v1 `StockNumbers`（舊程式會將它當作空白股號查詢），保留原設定並顯示法說會清單尚未套用；使用者須重新啟用公司或依已驗證的切換流程處理舊工作
