# Spec Delta

## Purpose

定義現有法說會蒐集與 Google Calendar 同步功能在桌面化後仍須維持的資料品質、去重、可恢復授權及執行狀態行為。

## ADDED Requirements

### Requirement: 擷取關注公司的法說會
系統 SHALL 依啟用的關注公司擷取近期法說會，保存公司、時間、地點、說明及來源連結，並呈現來源與最後同步狀態。

#### Scenario: 發現新的法說會
- **WHEN** 來源回傳關注公司且本機不存在的法說會
- **THEN** 系統保存活動並將其列為待同步行事曆

### Requirement: Google Calendar 同步避免重複
系統 MUST 在建立行事曆事件前重新查詢目標時段的 Google Calendar；本機既有同步狀態不得單獨視為遠端事件仍存在的證據。仍在未來且屬於啟用關注公司的已保存場次，即使來源當次不再列出，也 SHALL 納入複查；已過期或停用公司的場次不得補建。

#### Scenario: 法說會已同步
- **WHEN** 同一法說會已存在於設定的 Google Calendar
- **THEN** 系統不建立第二筆事件並記錄為已存在

#### Scenario: 使用者刪除既有的未來行事曆事件
- **WHEN** 本機曾記錄已存在或已同步的未來法說會，但 Google Calendar 現在查不到該事件
- **THEN** 系統再次同步時建立一筆相同摘要、時間、時區與提醒的事件並更新本機事件識別資訊；若查詢失敗則記錄失敗，不得假定不存在而建立

#### Scenario: 來源頁不再列出已保存的未來場次
- **WHEN** 來源本次不再列出一筆已保存、仍屬於啟用關注公司的未來法說會
- **THEN** 系統仍複查該場次的 Google Calendar 狀態並在缺少時補建，且不重複處理同批來源已有的場次或補建過期與停用公司的場次

### Requirement: 使用者可管理 Google 授權狀態
系統 SHALL 顯示 Google Calendar 是否已連線，並提供連線、重新授權與中斷連線操作。

#### Scenario: 憑證失效
- **WHEN** Google 拒絕已保存的授權憑證
- **THEN** 系統停止該次寫入、保留待同步項目並提示使用者重新授權

#### Scenario: 撤銷已失效授權時中斷連線
- **WHEN** 使用者選擇中斷 Google Calendar，而 Google 回覆 token 已失效或撤銷請求失敗
- **THEN** 系統仍清除 v2 本機加密保存的授權 token 並顯示未連線；非已失效錯誤須告知 Google 端撤銷未確認，不得刪除 v1 的 `token.json` 或既有法說會資料

### Requirement: 使用者可直接啟動 Google OAuth
系統 SHALL 使用由應用程式提供的桌面 OAuth client 設定。一般使用者 SHALL 可直接選擇連線並在系統瀏覽器完成授權，不得要求使用者自行建立或匯入 OAuth client JSON。

#### Scenario: 首次連線不需匯入 client JSON
- **WHEN** 使用者在尚未授權的應用程式選擇「連線 Google Calendar」
- **THEN** 系統使用應用程式的 OAuth client 啟動系統瀏覽器授權流程，並將取得的 token 加密保存；不要求使用者選取 OAuth 設定檔

### Requirement: 單筆失敗不阻斷整批處理
系統 SHALL 對每筆法說會分別記錄同步結果，使單筆資料或 API 錯誤不會取消其他可處理項目。

#### Scenario: 一筆事件格式錯誤
- **WHEN** 一批待同步活動中有一筆缺少必要時間資料
- **THEN** 系統將該筆標記失敗並繼續處理其他有效活動

### Requirement: 法說會保留每日自動執行
系統 SHALL 在 v2 安裝後保留每日法說會擷取與 Google Calendar 去重／同步能力，不得只提供手動按鈕。排程 SHALL 由 Windows 工作排程管理，使用既有法說會解析規則；同一 Windows 使用者不得同時啟用兩個會寫入同一行事曆的受管每日工作。

#### Scenario: 每日工作到期
- **WHEN** Windows 工作排程觸發唯一的法說會工作且 Google 授權有效
- **THEN** 系統依當前關注股號擷取法說會、排除過期與重複場次並記錄每筆結果；使用者不必開啟主視窗手動按同步

#### Scenario: 共存期間手動觸發
- **WHEN** 既有 v1 排程尚在使用，或法說會每日工作正在執行，而使用者要求手動同步
- **THEN** 系統不得啟動另一個可同時寫入同一行事曆的流程，並清楚顯示已交由既有工作處理或目前工作仍在執行

#### Scenario: 已停用舊工作時正式手動驗收
- **WHEN** 已精確辨識 v1 每日工作已停用且停止、v2 每日工作不存在，而使用者明確要求一次法說會同步驗收
- **THEN** 系統允許受單一執行閘門保護的手動擷取與 Calendar 查重／寫入，逐筆記錄結果；不得因此自動啟用每日 v2 工作，且工作狀態未知或 v1 仍在執行時必須拒絕
