# Spec Delta

## Purpose

定義非工程背景使用者可完成的 Windows 安裝、捷徑、升級與移除體驗，並確保版本更新不會遺失已累積的本機資料。

## ADDED Requirements

### Requirement: 提供單一 Windows 安裝流程
系統 SHALL 提供可互動執行的 Windows 安裝包，完成應用程式安裝、開始功能表項目與桌面捷徑建立。

#### Scenario: 首次安裝
- **WHEN** 使用者完成安裝精靈
- **THEN** 使用者可從桌面或開始功能表啟動應用程式且不需要另行安裝 Node.js

### Requirement: 安裝流程接續法說會每日工作
系統 SHALL 在首次安裝／首次啟動設定期間先辨識目前 Windows 使用者的既有 v1 法說會工作，包括 `stock-info-collector-daily-work` 與舊版 `stock-info-collector` 名稱，並讓使用者看見工作來源與就緒狀態。只有確定沒有可用的 v1 工作時，才 SHALL 建立使用 v2 隨包執行入口與加密授權的每日 19:00 Windows 工作排程；不得要求一般使用者安裝 Node.js、手動建立 OAuth client 或保存明文 token。

#### Scenario: 已有 v1 法說會工作
- **WHEN** 可精確辨識既有 v1 工作、執行檔、工作目錄與設定檔
- **THEN** 安裝流程保留其動作、時間與既有憑證，不建立第二個每日寫入者，並提供匯入／核對舊股號與後續管理入口

#### Scenario: 現有法說會工作最近一次未成功
- **WHEN** 已辨識的 v1 或 v2 每日工作回報非成功的最近執行結果
- **THEN** 系統顯示 Windows 結果碼與檢查提示，保留目前唯一受管工作，不把工作存在誤說成已成功執行，也不自動建立第二個寫入者；尚未首次執行的結果應與失敗區分

#### Scenario: 沒有 v1 法說會工作
- **WHEN** 已確認不存在既有受管 v1 工作且使用者完成 v2 首次設定
- **THEN** 系統冪等建立同使用者的每日法說會工作，執行目標在覆蓋升級後仍指向目前版本；Google 尚未授權時明示未就緒且不得寫入

#### Scenario: 既有工作狀態無法確認
- **WHEN** 工作排程查詢遭拒、名稱衝突或執行檔／設定檔無法辨識
- **THEN** 系統顯示需要處理的狀態，不把未知當作不存在、不覆蓋原工作，也不建立可能造成重複寫入的第二個工作

#### Scenario: 正式驗收後切換唯一每日工作
- **WHEN** v2 已完成正式來源、Calendar 去重／寫入驗收且作者選擇切換，現有 v1 工作可精確辨識為已停用且停止
- **THEN** 系統只在明確切換操作中建立 v2 每日 19:00 工作，保留 v1 工作為停用狀態供回退，並重新確認兩個既有 v1 工作名稱都沒有啟用、只有 v2 是啟用中的受管 Calendar 寫入排程；若任一檢查失敗，不得宣稱切換成功

#### Scenario: 升級既有的 v2 每日工作時間
- **WHEN** 使用者從每日 17:45 的 v2 安裝版升級，且目前使用者的 v2 工作名稱、動作、工作目錄、擁有者與唯一執行策略都能精確核對，v1 工作仍停用且停止
- **THEN** 系統備份原工作定義，只把同一 v2 工作的每日時間改為 19:00，再確認沒有第二個受管 Calendar 寫入者；若任一核對或修改失敗，保留原工作並顯示未就緒，不得把任意時間或同名異物當成 v2 工作

### Requirement: 升級保留使用者資料
系統 MUST 將應用程式檔案與使用者資料分開保存，使應用程式升級不覆寫資料庫、設定、紀錄與憑證。

#### Scenario: 安裝較新版本
- **WHEN** 使用者在既有版本上安裝新版
- **THEN** 新版沿用既有資料並執行必要的資料結構遷移

### Requirement: 升級前可選擇結束仍在執行的舊版
系統 SHALL 在單一安裝檔啟動 Squirrel 安裝前，辨識目前使用者已安裝且仍在執行的 v2 程序，明確詢問是否結束舊版。使用者拒絕、程序位置無法確認或結束失敗時 MUST NOT 啟動安裝；不得只憑相同執行檔名稱結束其他程式。

#### Scenario: 舊版仍在系統匣
- **WHEN** 使用者執行新版安裝檔，且已安裝的舊版仍在背景執行
- **THEN** 安裝前顯示可選擇的關閉提醒；同意後只結束已驗證的本產品程序，再啟動新版安裝

#### Scenario: 使用者拒絕關閉舊版
- **WHEN** 使用者在關閉提醒選擇取消
- **THEN** 舊版繼續執行，且新版安裝不會開始

### Requirement: 移除行為清楚揭露
系統 SHALL 在移除應用程式時清楚區分程式檔案與使用者資料，避免未告知即刪除歷史紀錄。

#### Scenario: 一般移除
- **WHEN** 使用者透過 Windows 移除應用程式
- **THEN** 系統移除程式本體與由 v2 建立且可精確辨識的工作，依已揭露政策保留使用者資料；既有 v1 工作、設定與 token 不得被移除
