# Spec Delta

## Purpose

定義本機 Windows 通知的彙總、點擊導覽與投遞紀錄，同時維持通知內容適量且為未來新增 Gmail 管道保留一致事件介面。

## ADDED Requirements

### Requirement: 單筆更新使用明確通知
系統 SHALL 在一次檢查只發現一筆需通知的新事件時，顯示包含事件類型、公司與主旨摘要的 Windows 通知。

#### Scenario: 發現一筆重大訊息
- **WHEN** 一次檢查只有一筆關注公司的新重大訊息
- **THEN** 系統顯示一則包含公司名稱與主旨的通知

### Requirement: 多筆更新合併為彙總通知
系統 SHALL 將同一次檢查發現的多筆事件合併成單一通知，內容至少顯示受影響公司數與事件數。

#### Scenario: 同次發現七筆事件
- **WHEN** 一次檢查發現三家公司共七筆新事件
- **THEN** 系統只發送一則可辨識「3 家公司、7 筆事件」的彙總通知

### Requirement: 點擊通知開啟對應內容
系統 SHALL 在使用者點擊通知時開啟應用程式並導向該事件或該批結果的已篩選列表。

#### Scenario: 點擊單筆重大訊息通知
- **WHEN** 使用者點擊只對應一筆重大訊息的通知
- **THEN** 系統直接顯示該筆重大訊息的完整詳情

#### Scenario: 點擊彙總通知
- **WHEN** 使用者點擊多筆事件的彙總通知
- **THEN** 系統顯示該次檢查新增事件的列表而非未篩選首頁

### Requirement: 違約交割通知顯示全市場與關注摘要
系統 SHALL 在每日違約交割揭露取得新結果時，顯示全市場筆數與其中關注公司筆數；若包含關注公司，通知內容 SHALL 優先列出關注公司。

#### Scenario: 揭露包含關注公司
- **WHEN** 本日全市場有兩筆違約交割揭露且其中一筆屬於關注公司
- **THEN** 系統顯示一則包含「全市場 2 筆、關注公司 1 筆」及該關注公司名稱的通知

### Requirement: 無新增內容時避免不必要通知
系統 MUST 在重大訊息檢查成功但沒有新訊息時保持安靜；系統 SHALL 允許使用者設定是否接收每日違約交割「本日無揭露」完成通知，且預設為啟用。

#### Scenario: 重大訊息沒有新增
- **WHEN** 定期重大訊息檢查成功且沒有發現新訊息
- **THEN** 系統更新工作狀態但不顯示 Windows 通知

#### Scenario: 本日無違約揭露
- **WHEN** 官方資料已更新至目標日期、結果為零筆且使用者啟用完成通知
- **THEN** 系統顯示一則「本日無違約交割揭露」通知

### Requirement: 來源異常通知具備降噪規則
系統 MUST 避免為單次暫時性來源錯誤立即打擾使用者，並 SHALL 在同一必要來源連續三次失敗或持續無法取得完整資料時發送一次異常通知；狀態恢復後 SHALL 重設連續失敗計數。

#### Scenario: 單次暫時失敗
- **WHEN** 必要來源第一次檢查失敗且先前狀態正常
- **THEN** 系統記錄並在介面顯示錯誤，但不發送異常通知

#### Scenario: 連續三次失敗
- **WHEN** 同一必要來源連續第三次無法完成檢查
- **THEN** 系統發送一則包含工作名稱、失敗次數及開啟來源狀態入口的異常通知

### Requirement: 通知失敗不影響資料保存
系統 MUST 先保存事件及投遞意圖，再嘗試通知，並記錄通知成功或失敗結果。

#### Scenario: Windows 通知無法顯示
- **WHEN** 新事件已保存但作業系統拒絕或無法顯示通知
- **THEN** 事件仍可在應用程式查看且系統留下通知失敗紀錄
