# Spec Delta

## Purpose

定義本機 Windows 通知的彙總、點擊導覽與投遞紀錄，同時維持通知內容適量且為未來新增 Gmail 管道保留一致事件介面。

## ADDED Requirements

### Requirement: 單筆更新使用明確通知
系統 SHALL 在一次檢查只發現一筆需通知的新事件時，顯示包含事件類型、公司與主旨摘要的 Windows 通知。

#### Scenario: 發現一筆重大訊息
- **WHEN** 一次檢查只有一筆關注公司的新重大訊息
- **THEN** 系統顯示一則包含公司名稱與主旨的通知

### Requirement: 多筆更新合併為彙總通知
系統 SHALL 將同一次檢查發現的多筆事件合併成單一通知，內容至少顯示受影響公司數與事件數。

#### Scenario: 同次發現七筆事件
- **WHEN** 一次檢查發現三家公司共七筆新事件
- **THEN** 系統只發送一則可辨識「3 家公司、7 筆事件」的彙總通知

### Requirement: 點擊通知開啟對應內容
系統 SHALL 在使用者點擊通知時開啟應用程式並導向該事件或該批結果的已篩選列表。

#### Scenario: 點擊彙總通知
- **WHEN** 使用者點擊多筆事件的彙總通知
- **THEN** 系統顯示該次檢查新增事件的列表而非未篩選首頁

### Requirement: 通知失敗不影響資料保存
系統 MUST 先保存事件及投遞意圖，再嘗試通知，並記錄通知成功或失敗結果。

#### Scenario: Windows 通知無法顯示
- **WHEN** 新事件已保存但作業系統拒絕或無法顯示通知
- **THEN** 事件仍可在應用程式查看且系統留下通知失敗紀錄
